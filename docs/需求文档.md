# 即时通讯系统需求文档

## 1. 项目概述

### 1.1 项目名称

IM 即时通讯系统（暂定）

### 1.2 项目目标

构建一个用于学习、演示和求职展示的即时通讯后端项目。项目以单聊和小群聊为核心，重点体现消息可靠性、断线同步、并发控制、服务可观测性等后端工程能力。

### 1.3 目标用户

- 注册用户：能够建立会话、发送和接收消息，并在重新连接后同步离线消息。
- 系统运营/开发者：能够通过日志、指标和管理接口观察服务运行状态并排查异常。

### 1.4 技术栈

- 语言：Go
- Web 框架：Gin
- 持久化：MySQL
- 缓存及在线状态：Redis
- 异步消息：Apache RocketMQ
- 实时连接：WebSocket

具体库、部署方式和版本在技术设计文档中确定。

## 2. 范围与阶段

### 2.1 MVP（第一阶段）

- 用户注册、登录和身份认证。
- 用户资料查询及按关键词搜索用户。
- 单聊会话创建、会话列表和成员权限校验。
- WebSocket 建连、鉴权、心跳、断开清理和重连。
- 文本消息发送、服务端确认、实时推送和历史消息查询。
- 客户端请求幂等、消息唯一标识、会话内顺序号。
- 离线消息增量同步、未读数和用户已读游标。
- 基础日志、健康检查、配置管理和自动化测试。

### 2.2 第二阶段

- 小群聊：建群、邀请/移除成员、退出群聊和群消息。
- 多端在线策略和跨网关实例消息路由。
- RocketMQ 异步推送、失败重试和死信/异常消息处理。
- 虚拟积分红包：发红包、抢红包、领取结果通知、过期退款和账目流水。
- 慢客户端隔离、限流和基础运维指标。

### 2.3 暂不纳入范围

- 真实货币充值、提现、支付渠道和真实资金结算。
- 音视频通话、端到端加密、大规模万人群聊。
- 图片/文件消息、消息全文搜索、复杂内容审核和多地域容灾。

以上能力可在核心链路稳定后评估，不作为 MVP 交付条件。

## 3. 核心业务需求

### 3.1 用户与认证

- 用户可以使用账号凭据注册和登录。
- 登录成功后签发有时效的访问凭证；受保护接口和 WebSocket 握手均需鉴权。
- 用户只能读取允许公开的资料字段，不能通过修改请求参数冒用其他用户身份。
- 登录失败、凭证过期和重复注册应返回稳定、可区分的错误码。

### 3.2 会话与成员

- 用户可通过完整用户名查找账号并发起单聊；同一对用户只使用一个单聊会话。会话列表和聊天标题显示对方昵称。
- 会话列表按最近活动时间排序，并提供最近消息摘要和未读数。
- 每次读取或发送消息前，服务端必须校验当前用户是会话成员。
- 后续群聊会话支持成员身份、群主/管理员权限和成员变更记录。

### 3.3 消息发送与接收

- MVP 仅支持文本消息；消息至少包含消息 ID、客户端消息 ID、会话 ID、发送者、会话序号、内容和服务端时间。
- 客户端通过 HTTP 提交消息，服务端持久化成功后返回发送确认；WebSocket 用于向在线接收端推送事件。
- 服务端确认表示消息已持久化，不代表接收端已收到或已读。送达状态和已读状态需分别表达。
- 客户端重试必须复用同一个客户端消息 ID；服务端对同一用户、会话和客户端消息 ID 做幂等处理，重试返回原消息结果，不重复创建消息。
- 同一会话的消息应有可比较的服务端顺序号。消息历史使用游标分页，避免深分页造成性能退化。
- 在线推送可能重复或丢失；客户端按消息 ID 去重，并可按会话游标从服务端补拉。

### 3.4 WebSocket 连接

- 连接建立时完成身份认证，并绑定用户、设备和网关节点信息。
- 实现心跳和读写超时；断开时清理连接及过期在线路由。
- 每条连接使用有界发送队列。慢客户端不得无限占用内存，应触发丢弃可恢复推送、断开并通过游标补拉等明确策略。
- 同一用户多端登录的在线、离线和消息同步策略需要保持一致，并在接口及文档中说明。

### 3.5 离线同步、未读与已读

- 客户端携带最后已处理的会话序号请求增量消息；服务端按序返回后续记录。
- 客户端检测到序号缺口时可以主动补拉。
- 已读状态以用户在会话中的最后已读序号为基准；未读数应能从已读游标和消息记录重建或校验。
- 在线推送不可作为离线消息的唯一存储或恢复来源。

## 4. 虚拟积分红包需求（第二阶段）

### 4.1 业务边界

- 红包仅使用系统内虚拟积分，不可充值、提现、兑换现金或对接真实支付。
- 用户只能在有权限的群聊中发红包和领取红包。
- 支持普通红包；随机金额红包可以作为后续扩展。
- 红包具有总金额、总份数、已领取份数、剩余金额、创建时间和过期时间。
- 红包过期后，未领取积分退回发红包用户。

### 4.2 一致性与安全要求

- 积分以整数最小单位存储，禁止使用浮点数进行金额计算。
- 扣减发红包用户余额、创建红包、写入积分流水必须在同一数据库事务中完成。
- 领取操作必须保证红包份数和金额不会超发；同一用户对同一红包最多成功领取一次。
- 余额变更必须有不可变的业务流水；每类业务操作使用唯一业务单号保证幂等。
- 红包领取成功后再通过事务 Outbox 发布群聊通知；MQ 发布失败不得回滚已经提交的积分交易，重试也不得重复入账。
- 过期退款任务可重复执行，且必须保证最多退款一次。
- 对发红包、领取红包等接口实施权限校验、参数校验和必要的频率限制。

### 4.3 异常与边界场景

- 红包不存在、已过期、已领完、用户重复领取、余额不足。
- 同一请求并发重试、多个用户同时争抢最后一个名额。
- 数据库事务失败、MQ 暂时不可用、过期任务重复执行。
- 通过积分账户流水核对红包发出金额、领取金额和过期退款金额。

## 5. 可靠性与异步事件

- 消息持久化与待发布事件使用 Transactional Outbox，避免数据库提交成功但事件永久未发布。
- Outbox 发布器可重试；发布成功后更新事件状态。进程在“MQ 已接收、数据库状态未更新”时崩溃，允许重复发布。
- MQ 消费者必须幂等；不能假设消息只投递一次。
- RocketMQ 用于持久化后的异步分发和业务事件处理，不替代 MySQL 中的消息历史与权威业务状态。
- Redis 用于缓存、在线状态和节点路由等场景；关键业务余额、消息历史和幂等事实以 MySQL 为准。
- Redis Pub/Sub 或在线推送不可作为可靠消息存储；客户端通过消息游标补拉弥补推送缺失。

## 6. 数据与接口约束

- 所有时间统一按 UTC 存储，展示层转换为用户时区。
- 主键、消息 ID、会话序号和业务幂等键的生成及唯一性策略在技术设计中明确。
- 列表接口采用游标分页并限制单页数量；请求体、文本长度和频率均需设上限。
- API 使用统一响应格式和错误码；日志不得记录密码、访问令牌等敏感信息。
- 数据库迁移应版本化，开发和测试环境可重复初始化。

## 7. 非功能需求

### 7.1 安全

- 密码使用成熟密码哈希算法存储，不保存明文密码。
- 对接口、WebSocket 和消息内容执行身份、成员权限及输入校验。
- 配置密钥通过环境变量或外部配置注入，不提交到代码仓库。
- 实施基础限流、连接数限制和敏感操作审计。

### 7.2 可用性与可恢复性

- 数据库事务保证核心写入原子性；异步任务可重试且有幂等保护。
- 服务重启后，持久化消息可查询，未完成的 Outbox 事件可继续投递。
- 健康检查区分进程存活和依赖可用状态。

### 7.3 性能与容量验证

- 建立可重复的基准测试，记录硬件配置、实例数、连接数、消息大小和测试时长。
- 至少测量 HTTP 发消息吞吐、端到端推送延迟、WebSocket 并发连接数和数据库查询耗时。
- 简历中的性能数字只能使用实际测试结果，并附带测试条件，不预先承诺未经验证的指标。

### 7.4 可观测性

- 结构化日志包含请求/追踪 ID、用户或会话等必要关联字段，但不泄漏敏感数据。
- 记录关键业务计数、错误率、延迟、活跃连接数、队列积压和重试次数。
- 为 MQ 消费失败、Outbox 积压、WebSocket 异常断开和红包对账差异提供可排查信息。

## 8. MVP 验收标准

- 两个用户可以建立单聊并进行实时文本通信。
- 非会话成员无法读取或发送该会话消息。
- 模拟发送请求超时并重复提交时，历史中只产生一条消息且返回结果一致。
- 接收端断线期间发送的消息，在重连补拉后按会话序号完整呈现。
- 推送重复时客户端可以去重；推送丢失时可通过游标补齐。
- 历史消息支持稳定的游标分页，跨页不重复、不遗漏已提交的消息。
- 自动化测试覆盖认证、权限、幂等、顺序、断线同步和关键故障路径。

## 9. 简历展示原则

- 重点描述亲自实现的机制、边界条件和验证方式，不把计划中的功能写成已完成成果。
- 可展示的工程亮点包括 Transactional Outbox、消息幂等、会话序号、断线补拉、WebSocket 背压、多端路由和虚拟积分账本。
- 性能数据应注明压测环境、负载和测量口径；不使用脱离条件的并发量或延迟数字。
- 红包模块应突出并发下金额/份数不超发、重复请求不重复入账、过期退款幂等及流水对账，而非仅描述“实现了抢红包”。

## 10. 待技术设计阶段确定

- RocketMQ Topic、消息键、顺序性范围、重试和死信处理方式。
- Redis Key 设计、过期策略、在线路由失效恢复和缓存一致性。
- 虚拟积分的初始化方式、账户冻结/扣减模型及红包随机分配算法。
- 单元测试、集成测试、故障注入和压测工具链。
